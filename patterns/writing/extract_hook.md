# extract_hook

为整篇内容提炼封面钩子（让人想翻页的那句）。

## 输入
- `title`: 文章标题
- `claims`: 各节 claim 列表

## 输出（JSON）
```json
{
  "hook": "封面主标题（12字以内，观点断言）",
  "subhook": "封面副标题（20字以内，补充信息）"
}
```

## 规则
1. hook 是断言，不是描述。坏："5条硬核准则分享"，好："AI 的自信是设计出来的"
2. 用数字制造具体感（"5条"比"几条"好）
3. 制造认知冲突（"你以为的 X，其实是 Y"结构）
4. subhook 回答"这跟我有什么关系"

## 成文版（长文标题 + 导语，配合 `skills/article-writing-from-topic` T-12）

同一套提炼动作，输出两种东西：文章标题进 `article.md` 的 `#`，导语进 `>` 引用块。

### 输入
- `topic`：主题
- `verified[]`：通过双源验证的 claims（**只有这些能进标题与导语**）
- `unverified_count`：单源/零源条数

### 输出（JSON）
```json
{
  "title": "文章标题（≤20字，断言）",
  "lede": "导语（≤80字：验证条数 + 最大分歧点）",
  "divergence": "这批结论里最互相打架的一处（可为空串）"
}
```

### 额外规则
5. **导语必须说出验证条数**，例如"4 条结论各有两个独立来源"——让读者知道这篇的可信度是怎么来的。
6. **导语必须点出最大分歧或最大缺口**：verified 为空就写"暂无通过双源验证的结论，正文从缺"，禁止用模糊措辞盖过去（对齐 T-03）。
7. `divergence` 只从 verified 里找；找不到就留空串，**不许编一个分歧来制造张力**。
8. 标题里的数字必须能在 `verified` 中回指到具体 claim；回指不到就删数字（对齐 W-27）。
9. 双源里有同注册域伪装（`blog.x.com` + `x.com`）时，标题不得使用"多方证实"类措辞（对齐 T-05）。
