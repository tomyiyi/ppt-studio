## 同一份底本，三种做法

底本 = `ppt-studio/projects/workflow_full`（18 页，讲我们自己的 PPT 工作流）。
取三页做对照：**封面 / 数据表页（八道门禁） / 机制约束页（一页只用一个图位）**。

| | A blueprint | B sketch-notes | C 现有管线 |
|---|---|---|---|
| 场景规格 | `technical-deepdive` | `workshop-teaching` | 无（直接切段填槽） |
| 视觉语言 | 工程图纸：暗底、细线、尺寸线、图签、等宽代号 | 教学工作卡：纸底、行线、页边批注、错对并排 | 暗调底图 + 遮罩 + 文字 |
| 封面做法 | 断言句 + 七阶段管线示意图（封面本身在讲内容） | 学习目标契约 + 三个可检验结果 + 前置卡 | 一个词「工作流」压在生成底图上 |
| 数据页做法 | 8 行 × 3 列判据/阈值，hairline 网格 + 来源行 | 8 行 × 4 列，多一列「性质」（✓必做 / !易错 / +新加） | 只截到 4 行，被拆到下一页 |
| 机制页做法 | 合规示意 + 违规详图 + 遮罩台阶 + 三条约束 | 错面/对面并排 + 遮罩台阶 + 三条约束 | 4 条 bullet 文字 |
| 门禁（vendor `svg_quality_checker --canonical-authoring --stage final`） | errors 0 / warnings 3 | errors 0 / warnings 3 | errors 0 / warnings 3（18 页全量） |
| 导出 | `A.pptx` 24,474 B / 3 slides / slide1 原生形状 107 个、文本段 32 段 | `B.pptx` 23,371 B / 3 slides / 原生形状 44 个、文本段 20 段 | `workflow_full.pptx` 4,815,824 B / 18 slides |

门禁明细：A/B 各 3 条 warning 同源 —— 中文字体族（`Noto Sans SC` / `ZCOOL KuaiLe`）不是 PowerPoint 内建安全字体，导出后在别的机器上可能替换。**这是决策点，不是 bug**：要么接受替换，要么定一套"设计层可用且 PPT-safe"的中文字体（现有 18 页 deck 用的是同一族，同样带这条 warning）。

## 已验证 / 未验证

- 已验证：三套样张同源同字号九档、门禁 exit 0、导出为可编辑原生形状（不是贴图）、截图逐页亲眼看。
- 未验证：只做了 3 页 × 2 套，没做完整 18 页；A/B 没配 agnes 生图（两个场景规格都明确要求"图只在提供证据时用"，且省一轮额度）；`ZCOOL KuaiLe` 手写体在真机 PowerPoint 里的替换效果没测。
- 已知取舍：A/B 的密排参考卡故意违反"每页少字"的直觉——场景规格里写了"参考卡允许高密度，按查表优化而非按阅读优化"。

## 我看到的三条结论

1. **差距不在模板数量，在于有没有"页面角色"这一层。** 现有管线只有 `cover/bullets/table` 三种角色；场景规格里一个 deck 有 10 种角色（学习目标 / 工作演示 / 常见错误 / 参考卡 / 理解检查…），每种有自己的证据义务和构图倾向。`table → 07_blank.svg` 就是把 8 种角色压成 1 个的证据。
2. **写作层同样不是"文笔"问题，是"一页一个主张"的约束问题。** A/B 的标题是断言（"一页只用一个图位"），C 的标题是话题（"5. 画 SVG 画布"）。断言标题会反过来逼内容压缩，话题标题允许 bullet 无限长。
3. **ppt-master 自带的设计层够用，不必去 GitHub 另找。** 第一方核验：`hugohe3/ppt-master` 58,151★ / MIT / 今天仍在 push；`guizang-ppt-skill` 27,394★（瑞士风版式锁与校验器可借）；`presenton` 10,995★（模板工具，无断言式写作层）。本机另外 6 套 PPT skill 经比对无一层明显更强。值得"吸收"而非"替换"的两件：guizang 的中文版式锁 + trae ppt-generator 的"每页一个 narrative job + 证据计划"。
