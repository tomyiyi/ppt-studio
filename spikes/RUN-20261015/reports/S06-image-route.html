5. 目检（看成品，含两个渲染环境真问题）

asset-demo 两页（00 封面=intent asset，01 要点=intent none）。首轮预览暴露：

5.1 根因 A：cairosvg 2.9.1 默认 unsafe=False，外链图片被替换为 32 字节占位符

$ python3.11（TAGS['image'] 探针，真实渲染中拦截 fetch 结果）
bytes: 32  b'<svg width="1" height="1"></svg>'   # 安全模式下外链图片=占位符，不是生图失败
$ /usr/local/bin/python3.11 -c "cairosvg.svg2png(url=..., unsafe=True)"   # 加 unsafe=True 后图片正常上屏

5.2 根因 B：字体族名 SmileySans（无空格）在 cairo/fontconfig 精确解析不命中 → 豆腐块

矩阵实测（cairosvg 2.9.1，同文本「三级配图路由」）：
  "Smiley Sans"  → 正常渲染（Smiley Sans 粗斜体）
  "SmileySans"   → 豆腐块 □□□□
  "sans-serif"   → Verdana（无 CJK 字形）→ 豆腐块
  "PingFang SC" / "Noto Sans SC" → 正常
fc-match "SmileySans" 能模糊命中，但 cairo 走 FcNameParse 精确匹配不命中；CSS 式逗号回退链在 cairo 里不生效。

如实声明：03:53 同一批 run3 SVG 曾渲染出正常中文，04:00 后同文件渲染为豆腐块；根因 B 可解释当前状态，但无法解释 03:53 为何正常（疑 fontconfig 缓存期间被重建）。S5 已提交预览按当时环境属实，不回改。两条根因均为渲染环境问题，未动任何判据；修复归 S7（render_svg_cairo.py 必须 unsafe=True + 字体族名规范化）。
